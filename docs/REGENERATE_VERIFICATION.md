# One Map 10.0.1 — Regenerate 修复与验证

## 复现到的具体问题

旧版 10.0 默认 `currentLayer = 'relief'`，而世界渲染器只允许政治或聚落图层显示城镇，只允许政治图层显示国界。因此文明数据存在、网格也已创建，画面仍像没有文明。新版本不改地貌、承载量、人口、聚落或国家形成算法。

原版实测：

| 状态 | 国家数 | 城镇数 | 城镇顶点数 | 城镇可见 |
|---|---:|---:|---:|---|
| 默认世界 Aereth-47 | 38 | 96 | 10290 | No |
| 重新生成 OneMap-regression-10 | 36 | 92 | 9954 | No |
| 同一世界切换 Realms | 36 | 92 | 9954 | Yes |

原版记录：`REGENERATE_10_0_REPRODUCTION.json`。修复前发现的问题是显示错误，不是默认种子才允许生成文明。

## 本次修改

1. 新世界与载入世界默认使用 Realms，并启用 Towns、Borders、Names；重新生成不沿用旧世界的诊断图层或关闭状态。
2. Landscape 也保留可关闭的城镇和国界，并生成当地城镇标签；专业诊断图层仍可专注自然数据。
3. 在现有地图标题和短提示中显示实际国家、城镇数量，不增加常驻面板。
4. 生成完成后核对世界、文明和渲染器绑定及城镇网格。无国家或无集中聚落的有效结果如实报告，不强塞国家。
5. 新模型生成失败或挂载失败时恢复旧世界、人口、国界、年份和世界镜头；旧世界不存在或底层图形上下文无法恢复时仍显示错误。
6. 文明、自然世界、城镇建筑与地理继承算法没有改变。原世界渲染文件只有两个可见性判断变化；测试对这两个明确改动逆向归一化后核对旧哈希，渲染几何保持不变。

## 测试结果

- `npm test`：33 项 Node 测试全部通过，包括原模型、地理继承、所有默认城镇布局和本次显示回归测试。
- `python tests/regenerate_browser.py`：17 项专门浏览器回归检查全部通过。
- `python tests/onemap_browser.py`：16 项原有单地图交互检查全部通过，已新增真实国家、城镇、边界可见性断言。

专门的浏览器检查包含：从板块图层且关闭所有文明开关后重新生成；连续 8 次成功生成；随机种子；同种子重放；进入新城镇并确认读取新世界；从城镇视图重新生成；推进到 410 年；真实保存与读取；主动注入一次文明生成错误和一次网格挂载错误并检查旧世界恢复；错误之后再次生成；390 像素手机布局。

没有意外 JavaScript 错误或外部网络请求。两个 `REGRESSION_INJECTED` 错误由测试脚本在独立浏览器上下文中主动制造，并非生产代码中的测试后门。

## 验证边界

浏览器为 Chromium，本次走 **Canvas 软件回退渲染路径**。没有在真实硬件 GPU、Safari 或所有可能的种子上验证。截图来自运行中的程序，不是生成式概念图。测试检查的是内部数据和可见性一致，不是模型科学性。

自然环境无法支持城镇时仍可能合法地产生零国家。此次修复不会为了有国家而改变自然地理。

## 修改文件与复跑

核心改动：`src/ui/world-ui.js`、`src/ui/onemap-ui.js`、`src/render/world-renderer.js`；同步了 `index.html`、版本、文档与测试。

```sh
npm run build
npm test
npm run test:regenerate
npm run test:onemap
```

应用离线运行，不需要 npm 包。浏览器测试另需 Playwright 和 Chromium；配置见 `tests/requirements.txt` 与 README。

## 旧版临时查看办法

右上角图层按钮 → **Realms**，并勾选 **Towns / Borders / Names**。这只是恢复显示，不会重新生成或修改当前历史。可以保存当前世界，再用修复版读取。
