# Map loading

In three cold Chromium loads, the default map's median time to a rendered,
usable screen fell from **44.46 s to 12.45 s** (**72% less waiting**, 3.57× faster).
The complete measurements are in [MAP_LOADING_RESULTS.json](MAP_LOADING_RESULTS.json).

| Default world, cold load | Before | After |
| --- | ---: | ---: |
| Run 1 | 44.46 s | 12.45 s |
| Run 2 | 59.42 s | 10.65 s |
| Run 3 | 42.12 s | 13.23 s |
| Complete cities generated by the UI thread | 78 | 0 |
| Initial terrain builds | 2 | 1 |
| Directory entries / sacred sites | 168 / 69 | 168 / 69 |

The default atlas used to build 78 complete city layouts synchronously while
assembling its landmark directory. This happened after `lastGenerationMs` was
recorded, so the reported generation time hid most of the actual loading screen.

The directory now queries the shared city generator for the information it needs.
It samples the same terrain, reserves the same precinct, and checks the same
street connectivity. A positive result also runs household placement and the
final unobstructed doorway check: a potential wonder with no usable entrance must
not become a directory entry. Queries omit context landscapes, decorations and
the remaining complete-city metadata. Explicit `site.building` access still
materializes the final building; ordinary index serialization does not.

Up to two short-lived workers precompute those exact queries while the main
thread attaches and draws the atlas. The completed index is ready before loading
finishes. Cancellation terminates both workers; unavailable or failed workers
fall back to the same exact synchronous queries. No parent-world buffers are
transferred away from the renderer.

Other changes remove work without reducing visible detail:

- Parent-cell colors are cached by world identity and all six physical inputs.
  Callers receive their own arrays; an edited field invalidates its cell.
- Continuous city collection skips the standalone terrain, water and backdrop
  meshes, which the atlas used to discard. Independent city scenes and exports
  retain their terrain. A standard city avoids 99,440 discarded triangles, plus
  any unnecessary standalone excavation clipping.
- GPU upload and picking/export share one Float32 array. Transferred worker
  buffers are retained directly instead of copied twice.
- World attachment resets the camera and streaming layer before building its
  terrain, so initial UI binding does not invalidate and rebuild the same mesh.
- Detailed road ribbons wait until their zoom range. A cleared renderer cannot
  reuse a road cache key without restoring its buffers. Failed world replacement
  also restores streaming when the previous camera was already inside a town.

## Verification

`tests/landmark-index.test.mjs` locks all 168 default directory entries, including
69 real sacred sites and nine eligible but unplaceable wonders, to the previous
directory's metadata hash. It checks another world, saved recipes, complete city
fingerprints and the final building API. A blocked-doorway counterexample checks
that a query cannot stop at successful precinct placement.

`tests/environment-cache.test.mjs` checks cache mutation/isolation, complete city
data and site sampling at coasts, glaciers and interpolation boundaries.
`tests/city-collection.test.mjs` compares every retained mesh byte, ownership
range and excavation between full/continuous collection and real worker/fallback
paths, including a cached-world request and underground geometry.

`tests/loading.browser.mjs` runs cold loads of the offline standalone HTML in
separate Chromium processes/profiles. It checks directory completeness, world
fingerprints, a single terrain build, city entry, same-seed regeneration and
failure recovery from a close town view. The benchmark measures bootstrap through
the first stable rendered frame, separately from the internal generation timer.
Timing is reported rather than enforced as a machine-dependent test threshold.

```sh
npm run build
PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core/index.mjs \
CHROMIUM_PATH=/absolute/path/to/chromium npm run test:loading-browser
```

Set `TELLURIC_HTML` to a previous bundle, `TELLURIC_BASELINE=1` to record its eager
work, and `TELLURIC_PERF_OUTPUT` to a separate output directory for before/after
comparison. The default is three cold loads with a 1480 × 980 viewport, reduced
motion and SwiftShader; these timings are comparisons on the same machine, not
promises for other GPUs or devices. Screenshots and JSON go to `previews/loading`.
